I recently came across [OmicIDX](https://omicidx.cancerdatasci.org/overview/what-is-omicidx) on LinkedIn. It's a public index of NCBI metadata, published nightly as [Parquet](https://parquet.apache.org/) files.

This past year I've spent a lot of tedious time searching the [SRA](https://www.ncbi.nlm.nih.gov/sra) by hand for project work. After reading the [OmicIDX guide](https://omicidx.cancerdatasci.org/guides/#python), I realized that with [Polars](https://pola.rs/), which I already know well, I could build a tool to send me a weekly report of new whole-genome sequencing (WGS) SRA run IDs for organisms I care about.

The result is [omics-sra](https://github.com/embedbio/omics-sra), which finds SRA runs by querying the OmicIDX Parquet file `run_with_study.parquet`.

Here's how it works:

- **Scheduling:** With Claude's help, I found [Amazon EventBridge](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-what-is.html), which triggers a Lambda function once a week.
- **Search:** The Lambda function queries the OmicIDX Parquet files for WGS runs matching the organisms listed in a configurable YAML file.
- **Results:** Matching SRA IDs are written to an S3 bucket, and I get an email listing the new ones. The first run reported every existing match; each run after that reports only what's new since the previous week.

The SRA is a rich source of data, and being able to search it programmatically is a real productivity boost. Similar tools exist, such as NCBI E-utilities and NCBI alerts, but this was a fun way to get familiar with OmicIDX and AWS EventBridge.
